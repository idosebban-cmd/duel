# Maze Race Implementation Plan

> **For agentic workers:** Use **subagent-driven development** or **executing-plans** to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Maze Race as a real-time Socket.IO game on the existing Render server, with lobby → countdown → race → result, Supabase `games` finalization, and challenge flow isolated from other games.

**Architecture:** In-memory game state on Node (parallel to Dot Dash), `mr:*` Socket.IO namespace pattern, HTTP create/join mirroring `/api/dotdash`, React pages + Zustand store, `game_type: 'maze_race'` in Supabase. **Move application:** validate and apply **on `mr_move`** (one cell per valid tap); **`mr_tick` every 50 ms** re-broadcasts `{ player1, player2 }` positions for sync and smooth opponent display (server may no-op if nothing changed).

**Tech stack:** Node (Express + socket.io), React + Vite + TypeScript + Tailwind + Framer Motion, Zustand, Supabase client (finalize `games` only), existing `connectSocket()` from `src/lib/socket.ts`.

**Spec:** [docs/superpowers/specs/2026-03-28-maze-race-design.md](../specs/2026-03-28-maze-race-design.md)
